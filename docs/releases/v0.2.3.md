# agent-application v0.2.3

**Released 2026-10-26. A patch release.** Since [v0.2.2](v0.2.2.md): generated Apps read only what the page shows, and the
agent's fallback model is `gpt-6.1-sol`. Image: `docker.io/oramasearch/agent-application:v0.2.3`.

This release is the tree of `dev` at `ba264e5` with these notes, the version and the README's release line.

## What it includes

| PR | Change |
|---|---|
| #52 | The prompt says to aggregate in SQL and page row-level reads with `LIMIT`/`OFFSET`, never `SELECT *` without `LIMIT`, and never to join whole tables in the App. `unbounded_selects()` flags a literal `sql(...)` statement with neither a LIMIT nor an aggregate, in validation and repair, naming the line. The fallback model is `gpt-6.1-sol` |
| #50 | The v0.2.2 release merge |

Why:
- A production App copied three whole tables into memory every ten minutes.
- Lake v0.7.2 answers `too_many_rows` to an App query past 5,000 rows.
- In Lake v0.7.2 people choose the agents' model per workspace (default `gpt-6.1-sol`), and the gateway applies that
  choice to this agent's calls. The fallback matters only when the agent is run without a Lake model.

## Not included

- Apps already generated are not changed. One that reads whole tables is fixed by a `repair` or `change` turn.
