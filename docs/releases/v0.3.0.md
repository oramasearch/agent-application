# agent-application v0.3.0

**Released 2026-11-16. A minor release.** The agent's licence and open-source preparation, the bus
consumer and conversation memory bounded, and the image's bases pinned by digest, since
[v0.2.7](v0.2.7.md). The bounded bus and memory change behaviour a caller can see and add settings,
which is why this is a minor release and not a patch. Image: `docker.io/oramasearch/agent-application:v0.3.0`.

This release is the tree of `dev` after #75 (`c9cc363`), with these notes and the version.

### The licence — #76

agent-application is released under the MIT licence, copyright OramaSearch, Inc. (`LICENSE`,
`COPYRIGHT`). Every source file carries `SPDX-License-Identifier: MIT`, added and checked by
`tools/spdx-headers.py`. `THIRD_PARTY_LICENSES` lists the licence of every dependency. Contributions
are made under `CLA.md` (contributors assign copyright to OramaSearch, Inc.), following
`CONTRIBUTING.md` and `CODE_OF_CONDUCT.md`. `tools/sbom.py` writes the software bill of materials in
SPDX 2.3 and CycloneDX, regenerated for this release.

### A security policy — #72

`SECURITY.md` says how to report a vulnerability privately and what we commit to in reply.

### The bus consumer claims only what it can run — #70

A task is claimed only when a worker is free to run it. Nothing is received while every worker is
busy, so claimed tasks (and their credentials) no longer wait in memory, and a task left unclaimed
stays on the bus for another replica. `AGENT_BUS_WORKERS` (default 4) run at once; one customer
holds at most `AGENT_BUS_TENANT_WORKERS` (default one fewer), so one tenant's burst cannot take
every worker.

### The conversation memory is bounded, and keyed by Lake's claim — #71

- At most `AGENT_CONVERSATIONS` conversations (default 256), each at most
  `AGENT_CONVERSATION_TURNS` turns (20) and `AGENT_CONVERSATION_BYTES` (1 MiB), all of them at most
  `AGENT_CONVERSATIONS_BYTES` (64 MiB); one idle for `AGENT_CONVERSATION_IDLE_SECONDS` (3600) is
  dropped.
- Every bus turn carries Lake's claim (task, account, workspace). A bus turn's conversation is keyed
  by the account and workspace of the claim plus its `conversation_id`, so a conversation id named
  in another tenant's turn reaches nothing. A direct `POST /v1/turn` keeps its own key in a separate
  namespace. Seeding from the `history` Lake sends works as before. A turn that raises is rolled
  back.

### The image's bases are pinned by digest — #73

Each `FROM` and `COPY --from` names the multi-platform index digest its tag pointed to. See known
issue 3: a merge left an unpinned build stage beside the pinned one.

### Prepared for a public export — #75

Links to issues and pull requests, internal names and wording are removed from the README, the docs
and the earlier release notes.

## Behaviour changes to know before it rolls

1. **A bus turn's conversation is scoped to the account and workspace of Lake's claim.** The same
   `conversation_id` in another account or workspace is another conversation.
2. **Conversations are forgotten** past the limits above, oldest or idle first.
3. **The bus consumer runs at most `AGENT_BUS_WORKERS` turns at once** and leaves the rest on the
   bus.

## Settings it needs

No setting is required. Seven optional settings are new, each with the default above:
`AGENT_BUS_WORKERS`, `AGENT_BUS_TENANT_WORKERS`, `AGENT_CONVERSATIONS`, `AGENT_CONVERSATION_TURNS`,
`AGENT_CONVERSATION_BYTES`, `AGENT_CONVERSATIONS_BYTES` and `AGENT_CONVERSATION_IDLE_SECONDS`.
`git diff v0.2.7..v0.3.0 -- src` adds no other environment read.

## Not included

- **Claiming tasks by reference and naming the task on every call** (#74, for lake#871): deferred
  for review, not in this release.

## Known issues

Security-relevant first.

1. **Library agents hold live task credentials for every tenant they serve**: one shared process
   claims tasks for every person, each with a credential that acts as that person. A design issue
   on Lake's side.
2. **The image bundles GPL and LGPL code** (#77): it is built on `python:3.12-slim` (Debian: glibc,
   bash, coreutils, dpkg, readline), so the image is not published. It moves to `scratch` with
   static binaries before it is.
3. **The Dockerfile has two stages named `build`** (#78): a merge kept the pre-pin stage, which
   uses the bases by tag only and is the one that builds the venv, beside the pinned one. The digest
   pins of #73 do not yet hold for the build stage.
4. **Confirmation gates do not establish a separate human confirmer** (lake#989, low).
5. **`ensure_repository` does not match and create repositories in the turn's workspace** (#18): a
   repository with the same name in another workspace makes the deploy fail with a conflict.
6. **No explicit workspace IDs on data-plane calls** (#3), and no idle backoff on the bus.
7. **Generated Apps may still select whole tables** (#51) where they should aggregate in SQL and
   page row-level reads.
8. **No evals for repair and change turns** (#41).

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Moving a Lake to
`:v0.3.0` is a separate change to the operator's defaults or the Lake's resource.
