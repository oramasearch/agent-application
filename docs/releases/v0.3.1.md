# agent-application v0.3.1

**Released 2026-11-16. A patch release.** The Dockerfile has one build stage again, pinned by digest,
since [v0.3.0](v0.3.0.md). It fixes v0.3.0's known issue 3 (#78). Nothing the agent does has
changed. Image: `docker.io/oramasearch/agent-application:v0.3.1`.

This release is the tree of `dev` after #82 (`7a85b94`), with these notes and the version.

## What changed

Every pull request merged into `dev` since `v0.3.0`
(`git log --first-parent v0.3.0..origin/dev`):

| PR | What it does |
|---|---|
| #81 | Records the v0.3.0 image digest in the v0.3.0 notes; documentation only |
| #82 | One digest-pinned `build` stage: the unpinned stage a merge had left beside it is removed, so the venv is built on the pinned bases. Fixes #78 |

### One build stage, pinned by digest — #82

In v0.3.0 the Dockerfile had two stages named `build`. The second, which builds the venv, named
`python:3.12-slim` and `ghcr.io/astral-sh/uv:0.11.7` by tag only, so the digest pins did not hold
for it. Now there is one `build` stage, and every `FROM` and `COPY --from` names the
multi-platform index digest of its tag. The bases are the same digests v0.3.0 pinned. The comments
in the Dockerfile header no longer reference internal issues.

No source file under `src/` changed, and no setting is new or removed
(`git diff v0.3.0..v0.3.1 -- src` is empty).

## Known issues

Security-relevant first.

1. **Library agents hold live task credentials for every tenant they serve**: one shared process
   claims tasks for every person, each with a credential that acts as that person. A design issue
   on Lake's side.
2. **The image bundles GPL and LGPL code** (#77): it is built on `python:3.12-slim` (Debian: glibc,
   bash, coreutils, dpkg, readline). The move to `scratch` with static binaries is deferred; it is
   noted here and does not block this release.
3. **Confirmation gates do not establish a separate human confirmer** (on Lake's side, low).
4. **`ensure_repository` does not match and create repositories in the turn's workspace** (#18): a
   repository with the same name in another workspace makes the deploy fail with a conflict.
5. **No explicit workspace IDs on data-plane calls** (#3), and no idle backoff on the bus.
6. **Generated Apps may still select whole tables** (#51) where they should aggregate in SQL and
   page row-level reads.
7. **No evals for repair and change turns** (#41).

v0.3.0's known issue 3, the two `build` stages (#78), is fixed by #82.

## Where it has run
