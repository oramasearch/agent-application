# agent-application v0.2.1

**Released 2026-10-25. A patch release.** One change since [v0.2.0](v0.2.0.md): the Application Agent
can **repair** an App that failed and **change** an existing App from more instructions, always as a
diff the person confirms, plus Lake's opt-in auto-fix. Image: `docker.io/oramasearch/agent-application:v0.2.1`.

It is a patch: the existing turns (design, confirm, deploy) and every setting are unchanged; the two
new turn kinds are only sent by a Lake that carries lake#1218.

This release is the tree of `dev` at `73efc06` with these notes, the version and the README's release
line.

How it works: [repairing and changing an App](../building/repair.md),
[building, confirming and deploying Apps](../building/apps.md), [service and bus operation](../operations/service.md).

### Repair and change turns

- **Reads the App's facts:** `receive_app_events`, `app_logs` (when logs are unavailable it says so,
  lake#1206, and never gives missing logs as the
  reason), `list_builds` and `build_logs`, and every file under the App's folder, from the source Lake
  recorded at the last deploy when the App runs a built image.
- **Proposes, writes nothing:** the proposal is `{kind: proposal, confirm: true, turn, diagnosis, diff,
  files, delete, app}`, holding only the changed files and a unified diff computed by the agent, not
  the model. It is checked before it is shown: safe paths, the code compiles, no secret literal or
  turn credential, `app.toml` keeps its name, framework and port, and at least one file changes. A
  failed check goes back to the model, twice at most.
- **On confirm** (`context.confirmed_proposal`): refuses a proposal for another App, commits the files
  on `main` in one `commit_repository_files` (each write a liquid drip attributed to the person), sets
  `APP_DEPS` and builds when a package outside app-runtime's baked set is now needed, deploys the new
  revision or image, follows the rollout and reports.
- **Auto-fix** (`context.auto_fix: {attempt, max_attempts}`, granted by Lake only when the person opted
  in): applies its own proposal, names the attempt, and writes nothing when it finds no fix.
- `Turn.kind` comes from the body's `kind`; `list_builds` and `get_auto_fix` join the read set. New
  prompt `prompts/repair-v1.md`; the design prompt is still `v1`.

### Settings it needs

No new setting. The settings of [v0.2.0](v0.2.0.md#settings-it-needs) still apply
(`AGENT_SERVICE_TOKEN` and `LAKE_URL` required, `AGENT_MODEL` read, all rendered by the operator).

The new turns need the Lake that sends them, grants their tools and holds the auto-fix gate:
lake#1218, merged into lake's `dev` on 2026-10-25 and
not in a lake release yet (lake v0.7.0 does not have it). An older Lake never sends `repair` or
`change`.

## What it does not include

Unchanged from [v0.2.0](v0.2.0.md#what-it-does-not-include):

- no conversation memory that survives the process; `prior_turn` is not read;
- no explicit `workspace_id` on its calls;
- no creating secrets;
- no frameworks beyond FastAPI, Streamlit and static sites;
- no idle backoff on the bus;
- no live eval result, and no eval cases yet for repair and change turns.

## Known issues

Security-relevant first. All open at this tag.

1. **Library agents hold live task credentials for every tenant they serve**.
2. **The bus consumer claims tasks into an unbounded queue before a worker is free**.
3. **Conversation histories are unbounded**.
4. **A confirmed turn cannot create an App with a Lake secret reference**.
5. **Confirmation gates do not establish a separate human confirmer**
   (lake#989, low). Auto-fix applies its own
   proposal without a confirm, by design, only when the person opted in on Lake.
6. **Repair and change turns are proven with scripted model answers only**, and have not run against a live
   Lake carrying lake#1218.
7. **App logs may be unavailable**; a
   repair then works from events, build logs and source.
8. **A repository with the same name in another workspace makes the deploy fail with a conflict**.
9. **No explicit workspace IDs, and no idle backoff on the bus**.
