# agent-application v0.2.0

**Released 2026-10-25. A minor release.** Six pull requests since [v0.1.0](v0.1.0.md), most of them
fixes from the 2026-10-21 security review: the service token is compared in constant time and turns
are refused when it is unset, a turn's credential goes only to the service's own `LAKE_URL`, and no
turn trace is kept on the pod's disk. It also proposes Lake's secret references and takes the Lake's
`AGENT_MODEL`. Image: `docker.io/oramasearch/agent-application:v0.2.0`.

This release is the tree of `dev` at `32caa4c` with these notes and the version.

How it works: [service and bus operation](../operations/service.md),
[building, confirming and deploying Apps](../building/apps.md), [evaluation scenarios](../evals/scenarios.md).

## What it includes

Every pull request merged into `dev` since `v0.1.0`:

| PR | Change |
|---|---|
| #29 | `POST /v1/turn` compares the bearer with `hmac.compare_digest`, and **fails closed**: with `AGENT_SERVICE_TOKEN` unset or empty every turn is refused with `503` (it used to be open). A wrong or missing bearer is still `401` |
| #31 | A turn's credential goes only to Lake at this service's own `LAKE_URL`, for capabilities and the model gateway alike. The turn's `lake_url` is ignored. `LAKE_URL` must be an absolute http(s) URL with a host and no user info, query or fragment; otherwise, or when unset, the turn is refused before any request goes out |
| #27 | A turn keeps nothing on the pod's disk: no `<TRACE_DIR>/<trace_id>.json`. `TRACE_DIR` is no longer read; the answer still carries `trace_id`. Lake keeps the answer in the task's sealed record in the workspace Zetta |
| #28 | A secret environment value must be one of Lake's two reference forms, `{"secret": {"mount_id", "name", "field"}}` or `{"secret": "lake-secret://<mount id>/<name>#<field>"}`. A Kubernetes Secret name is refused. The prompt (still `v1`) proposes a reference only when the person named an existing secret, and otherwise leaves the variable out and points to the App's Environment settings |
| #32 | The model is `APPLICATION_AGENT_MODEL` when set, else the Lake's `AGENT_MODEL`, else `gpt-5.5`, so the Lake's `spec.agents.model` now reaches this agent |
| #26 | Records the v0.1.0 image digest in the v0.1.0 notes |

### Settings it needs

| Variable | Why | Who sets it |
|---|---|---|
| `AGENT_SERVICE_TOKEN` | Now required: without it every `POST /v1/turn` is `503`. Bus turns do not use it | The operator, on every library agent pod |
| `LAKE_URL` | Now required for every turn, and must be a clean absolute http(s) URL | The operator |
| `AGENT_MODEL` | Now read; `APPLICATION_AGENT_MODEL` still overrides it | The operator, from `spec.agents.model` |

No new setting. The operator still sets `TRACE_DIR=/tmp/traces`; the agent ignores it. A hand-run
service must now set `AGENT_SERVICE_TOKEN` and `LAKE_URL`.

## What it does not include

Unchanged from [v0.1.0](v0.1.0.md#what-it-does-not-include), except that turn traces are gone:

- no conversation memory that survives the process; `prior_turn` is not read;
- no explicit `workspace_id` on its calls;
- no creating secrets;
- no frameworks beyond FastAPI, Streamlit and static sites;
- no idle backoff on the bus;
- no live eval result: the live evals need a live model and were not run.

## Known issues

Security-relevant first. All open at this tag.

1. **Library agents hold live task credentials for every tenant they serve**: one shared process claims tasks for
   every person, each with a credential that acts as that person. A design issue on Lake's side.
2. **The bus consumer claims tasks into an unbounded queue before a worker is free**: claimed tasks wait in
   the executor holding their credentials.
3. **Conversation histories are unbounded**: they are never evicted
   from the process's memory.
4. **A confirmed turn cannot create an App with a Lake secret reference**: Lake checks a reference with the
   caller's `get_secret_mount` and `read_secret`, which a confirmed turn's task credential lacks. The
   agent now proposes the right form; creating the App with it waits on Lake.
5. **Confirmation gates do not establish a separate human confirmer**
   (lake#989, low).
6. **A repository with the same name in another workspace makes the deploy fail with a conflict**.
7. **No explicit workspace IDs, and no idle backoff on the bus**.
8. **Lake's e2e T11 and T12 confirm without `proposal_task_id` and `proposal_sha256`**, so Lake refuses
   the confirming turn. The script is
   out of date, not this agent; until it is fixed the e2e gate does not exercise the confirm step.
9. **The model is offered reads a design turn cannot make**: `build_logs`, `get_build` and
   `receive_build_events` come back as errors on a design turn.

## Where it has run

**The v0.2.0 tree had not run on a development environment when it was released.** Every Lake ran the
operator default, `oramasearch/agent-application:v0.1.0` (orama-operator
`internal/controller/lake_defaults.go`). Moving the default to `:v0.2.0` is a separate operator change.
